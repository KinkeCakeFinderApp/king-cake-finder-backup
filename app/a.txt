SECTION 0 — WHY "CONTACT SUPPORT / CONTACT ADMIN" WASN'T WORKING
===========================================================================
There were TWO separate causes:

1) SENDING a support message needs the Firestore security rules for the
   "supportTickets" collection to be live. If your deployed rules don't
   include that block, sending fails with "permission denied".
   FIX = re-deploy the rules (SECTION 2).

2) The admin "Support requests" list (and the Moderation queue) used a
   database query that needed a special "composite index" you never
   deployed, so the lists came back empty / errored. I changed the code so
   it no longer needs any special index.
   FIX = get the latest code and rebuild (SECTION 1).

Do SECTION 1 + SECTION 2 and contact support works end-to-end.

Is contact-support OK for the app stores? YES. An in-app support/contact
form is allowed and even encouraged. Both stores also want a "support URL"

===========================================================================
SECTION 2b — HOW TO MAKE YOURSELF (OR SOMEONE) AN ADMIN
===========================================================================
For security, the app can NO LONGER create admins — anyone who inspected the
app used to be able to make themselves an admin, so that was removed. Admins
are now made by hand in the Firebase console:

  1. Have the person sign up a normal account in the app/website first.
  2. Firebase console -> Firestore Database -> Data.
  3. Open the "users" collection and find their document (the id is their
     account's UID; the doc shows their username/email).
  4. Click the "role" field, change its value from  user  to  superuser,
     and save.
  5. They may need to sign out and back in. The Admin tab now appears for them.

To REMOVE an admin, set the same field back to  user .
